# Vibelo 推荐模型训练与发布

## 结论

生产召回分为两层，不能混为一谈：

- `tools/train_two_tower_recall.py` 才是真正训练神经双塔召回模型的脚本。它训练共享图片投影和序列用户塔，产出版本化 checkpoint、manifest 与候选注册记录。
- `tools/train_recommendation_recall.py` 只搜索行为权重、时间衰减和浏览时长增益，服务于无模型或模型故障时的启发式 fallback。它不会训练神经网络，也不会生成双塔索引。

数据不足时继续使用启发式多兴趣召回是正常状态。不要伪造行为数据，也不要把 synthetic smoke 模型发布到生产。

## 双塔结构与样本

图片塔输入现有 512 维 SigLIP2 向量，经过可训练共享投影得到归一化的 256 维向量。用户塔读取按时间排列的行为序列，将历史图片投影、行为类型、时间间隔与浏览时长送入 Transformer/attention，再输出同一 256 维空间的归一化用户向量。

训练样本遵循以下规则：

- `favorite`、`like`、`comment`、`share`、`click` 为正反馈；`view` 只有达到 3 秒才算正反馈。
- 每个用户或访客的每个“下一个正反馈”都可以成为目标，同一交互链中的同一图片不会重复成为标签，也不会泄漏进历史序列。
- 24 小时前曝光且此后没有正反馈的图片可作为 hard negative。
- 全部样本按全局时间顺序做 80%/10%/10% 的训练、验证、测试划分，避免未来数据泄漏。
- 损失使用 InfoNCE、batch 内负样本和重复目标遮罩；验证与测试记录 `recall@10`、`recall@50`、`mrr`。

## 生产门禁

真实训练默认至少需要：

- 50 个有正反馈且历史、目标向量完整的 actor；
- 500 条有效 next-positive 样本；
- 每个时间切分至少 2 条样本；
- validation `recall@50 >= 0.01`；
- test `recall@50 >= 0.01`。

任一数据门禁不满足时，训练直接失败且不注册 candidate。指标门禁不满足时可以留下版本文件用于排查，但不注册 candidate，流水线也会以非 0 状态停止。`--synthetic-smoke` 只验证代码路径：它不会注册 candidate，注册器也禁止 synthetic 版本 promote。

生产定时任务不要降低以上阈值，也不要向索引发布脚本传 `--allow-unsafe`。指标阈值 0.01 只是防止完全失效的最低保护线，上线积累足够数据后应根据离线基线和线上 A/B 结果逐步提高。

## 环境与持久化

先安装项目内推荐依赖，并保证 MySQL 与 Milvus 可访问：

```powershell
.\tools\.venv\Scripts\python.exe -m pip install -r tools\requirements_recommendation.txt
$env:VIBELO_RECOMMENDATION_MODEL_DIR="D:\vibelo-data\recommendation-models"
```

训练任务、发布任务和在线模型服务必须使用同一个 `VIBELO_RECOMMENDATION_MODEL_DIR`。该目录应放在持久化磁盘或挂载卷中，不能放入容器临时层：

```text
recommendation-models/
  recall_metadata.json                 # 启发式 fallback 参数
  ranker.joblib                        # 精排模型（若已训练）
  ranker_metadata.json
  two_tower/
    registry.json                      # candidate/current/previous
    versions/
      <version>/
        model.pt
        manifest.json
```

同时保留 Milvus 数据卷。不要删除 `registry.json` 中 `current` 或 `previous` 所引用的版本目录和 Milvus collection，否则在线热加载或回滚会失败。

## 真实训练

默认参数已经包含低数据门禁、CUDA 自动选择、AMP、early stopping 和固定随机种子：

```powershell
.\tools\.venv\Scripts\python.exe tools\train_two_tower_recall.py `
  --days 180 `
  --limit 2000000 `
  --batch-size 128 `
  --epochs 20 `
  --patience 3
```

常用可调参数可通过帮助查看：

```powershell
.\tools\.venv\Scripts\python.exe tools\train_two_tower_recall.py --help
```

只有真实数据与指标门禁同时通过时，脚本才把新版本写入 `two_tower/registry.json` 的 `candidate`。训练不会直接替换线上 `current`。

## Synthetic smoke

代码或依赖升级后可以运行隔离 smoke。默认输出到系统临时目录；也可显式写到测试目录，但不要使用生产模型目录：

```powershell
.\tools\.venv\Scripts\python.exe tools\train_two_tower_recall.py `
  --synthetic-smoke `
  --synthetic-examples 96 `
  --epochs 4
```

synthetic 产物永远不可 promote。

## Candidate 到上线

发布状态机为：

```text
训练通过 -> candidate(PENDING) -> 构建并校验 Milvus 索引
         -> candidate(READY)   -> promote -> current
                                              原 current -> previous
```

先读取训练刚注册的 candidate 版本：

```powershell
$registryPath = Join-Path $env:VIBELO_RECOMMENDATION_MODEL_DIR "two_tower\registry.json"
$registry = Get-Content $registryPath -Raw -Encoding UTF8 | ConvertFrom-Json
$version = [string]$registry.entries.candidate.version
if (-not $version) { throw "No publishable two-tower candidate" }
```

可先做只读预检。`--dry-run` 会读取全部已发布图片、检查原始向量并运行图片塔编码，但不创建 learned collection，也不改 registry：

```powershell
.\tools\.venv\Scripts\python.exe tools\publish_two_tower_index.py `
  --model-dir $env:VIBELO_RECOMMENDATION_MODEL_DIR `
  --version $version `
  --dry-run
```

构建并校验版本化 Milvus 索引，但暂不切流：

```powershell
.\tools\.venv\Scripts\python.exe tools\publish_two_tower_index.py `
  --model-dir $env:VIBELO_RECOMMENDATION_MODEL_DIR `
  --version $version `
  --batch-size 512
```

确认 candidate 的 `index.status` 为 `READY` 后 promote。发布器会再次校验模型 checksum、维度、实体数量、抽样向量范数和安全门禁：

```powershell
.\tools\.venv\Scripts\python.exe tools\publish_two_tower_index.py `
  --model-dir $env:VIBELO_RECOMMENDATION_MODEL_DIR `
  --version $version `
  --promote
```

`--limit` 只适合隔离索引测试，生成的 partial index 永远不能 promote。生产重建现有同版本 collection 前应先确认它没有被 `current`/`previous` 引用；日常流水线不使用 `--rebuild`。

## 一键安全流水线与定时任务

仓库提供的 PowerShell 流水线会按顺序执行真实训练、读取 candidate 版本、构建完整索引、验证并 promote。任一步骤失败都会停止；脚本固定保留 50 actors、500 examples 和默认指标门禁，不传任何 unsafe 参数：

```powershell
.\tools\run_two_tower_pipeline.ps1 `
  -ModelDir "D:\vibelo-data\recommendation-models"
```

Windows 任务计划程序可在每天低峰期执行：

```text
程序: powershell.exe
参数: -NoProfile -ExecutionPolicy Bypass -File "G:\path\RanGwaz\tools\run_two_tower_pipeline.ps1" -ModelDir "D:\vibelo-data\recommendation-models"
起始位置: G:\path\RanGwaz
```

当前行为量不足时，任务失败并保留线上 `current` 不变，这是正确结果。先继续收集曝光、点击、长浏览、点赞、收藏、评论和分享，再由下一次定时任务自然通过门禁。

启发式 fallback 参数与精排可以独立定时更新；前者不是双塔训练：

```powershell
.\tools\.venv\Scripts\python.exe tools\train_recommendation_recall.py --mode auto --days 60
.\tools\.venv\Scripts\python.exe tools\train_recommendation_ranker.py --mode auto --days 45 --min-behavior-positives 200
```

## 回滚

`promote` 会自动把原 `current` 保存为 `previous`。线上指标变差时执行原子槽位交换，恢复上一个已验证模型与索引：

```powershell
$env:VIBELO_RECOMMENDATION_MODEL_DIR="D:\vibelo-data\recommendation-models"
.\tools\.venv\Scripts\python.exe -c "import json; from tools.two_tower_registry import rollback; print(json.dumps(rollback(), ensure_ascii=False, indent=2))"
```

回滚后再次检查 `/health`。`previous` 与刚撤下的版本会交换，因此同一命令可在确认后 roll-forward。

## 在线健康检查与降级

模型服务按 `registry.json` 修改时间热加载 `current`，不会读取 `candidate`。检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8092/health | ConvertTo-Json -Depth 8
```

上线要求：

- `milvusReady` 为 `true`；
- `twoTowerLoaded` 为 `true`；
- `twoTowerVersion` 等于 registry 的 `current.version`；
- `twoTowerIndexCollection` 非空且与 current 的 READY index 一致；
- `twoTowerLoadError` 为空。

`POST /recall/home` 成功使用学习模型时返回 `mode=trained-two-tower`、`source=learned-two-tower` 和模型版本。registry 不存在、没有 current、checkpoint/checksum/维度不匹配、learned collection 不可用、历史不足或推理异常时，服务自动回退到现有的多兴趣 SigLIP 启发式召回；Java 侧仍保留多路规则链路。发布后必须同时验证学习路径和故障回退路径。

## 上线验收

- 对完整线上图片集合构建索引，Milvus 实体数与已发布且有原始向量的图片数一致。
- 停止或隔离 learned collection 后，首页仍能通过 fallback 返回内容。
- 连续翻页保持同一个 `refreshSeed`，手动刷新生成新 seed。
- `feed_impressions` 只记录真实进入可视区的曝光，`event_id` 去重有效。
- 监控 CTR、详情到达率、长浏览率、收藏率、重复曝光率、模型服务耗时和 fallback 比例。
- 先小流量观察，再根据线上指标决定是否保持 current 或 rollback。
