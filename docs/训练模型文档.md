# Vibelo Recommendation Model Roadmap

## Target Chain

The production home feed should run as:

1. Collect behavior events from home, detail, interaction, follow, search, and publish flows.
2. Build a recent user sequence from impressions, clicks, views, likes, favorites, comments, shares, and follows.
3. Recall candidates from multiple routes:
   - sequence-aware vector recall from the model service
   - tag/topic/category recalls from MySQL
   - followed-author recall
   - global cold-start recall
4. Merge and de-duplicate candidates in Java.
5. Rank candidates with the model service.
6. Apply business guards: seen penalty, author/category diversity, freshness, and safe fallback.
7. Track impressions and downstream behavior for training labels.

## Current Implementation

- `tools/recommendation_model_service.py` serves:
  - `POST /recall/home` for sequence-aware vector recall over Milvus.
  - `POST /rank/home` for home-feed ranking.
  - `GET /health` for deployment checks.
- `tools/train_recommendation_ranker.py` trains a first ranking model.
  - In `auto` mode it uses real impressions when enough positives exist.
  - Before launch traffic exists, it falls back to bootstrap labels from item quality, freshness, and metadata completeness.
- The backend has feature flags:
  - `app.recommendation.model-recall-enabled`
  - `app.recommendation.model-ranking-enabled`
  - `app.recommendation.model-service-url`
- If the model service times out or returns an error, Java falls back to the existing vector/rule ranking chain.

## Local Commands

Install or update Python dependencies:

```powershell
pip install -r tools/requirements_recommendation.txt
```

Train a bootstrap ranker:

```powershell
python tools/train_recommendation_ranker.py --mode bootstrap --limit 80000
```

After collecting real traffic, train from behavior labels:

```powershell
python tools/train_recommendation_ranker.py --mode behavior --days 45 --limit 120000
```

Run the model service:

```powershell
.\tools\run_recommendation_model.ps1
```

Enable model ranking in `backend/src/main/resources/application.yml` or environment-specific config:

```yaml
app:
  recommendation:
    model-service-url: http://127.0.0.1:8092
    model-recall-enabled: true
    model-ranking-enabled: true
```

## Launch Gate

Before public traffic, keep model flags off unless these checks pass:

- Milvus collection health is green and entity count matches the vectorized image count.
- `GET /health` on the model service reports `milvusReady=true`.
- The backend still returns `/feed` when the model service is stopped.
- Impressions, clicks, views, likes, favorites, comments, and shares are written to `user_behaviors`.
- Feed pagination keeps one `refreshSeed` stable across page 1, page 2, and page 3.
- A manual refresh creates a new `refreshSeed` and can produce a different order.

## Next Upgrade After Public Data

When real traffic exists, replace the bootstrap ranker with:

- a two-tower or sequence user-tower recall model trained from positive behavior sequences
- a LightGBM/XGBoost LambdaRank ranker trained from impression groups
- online metrics for CTR, detail-view rate, favorite rate, long-view rate, and duplicate exposure rate
- Redis feed/session cache keyed by user id plus refresh seed
